- JavaScript 객체를 사용할 것, 객체 지향적인 설계를 배움과 연습하며 객체를 클래스나 팩토리 함수를 사용하여 생성할 것

## 3주차 시작 전 기능 구현

- 구입 금액의 입,출력 구현하기
- 1,000원 단위로 나누어 떨어지지 않을 경우 단위 테스트 작성하기
- 구입 금액을 입력한 값에 따라 로또 구매 기능 구현
- 구매 로또 번호 오름차순으로 정렬 후 출력
- 당첨 번호 입,출력 받기
- 당첨 번호에 중복된 숫자, 46 이상의 숫자, 음수를 입력했을 때, 숫자를 입력하지 않았을 때 단위 테스트 진행하기
- 보너스 번호 입, 출력 받기
- 당첨 번호에 보너스 번호를 입력했을 때, 46 이상의 숫자, 음수를 입력했을 때, 숫자를 입력하지 않았을 때 단위 테스트 진행하기
- 당첨 통계 출력 구현하기
- 로또 한개가 당첨번호와 몇개가 일치하는지 구현하기
- 총 당첨 금액에 따라 로또 구매 금액을 통해 수익률 구현하기 (소수점 둘째 자리 반올림)

## 3주차 커밋과 기능 구현 추가 내용

- README 파일 작성 완료
- 입, 출력을 class 별로 구현 후 각각의 SRP을 준수하도록 받음
- 구입 금액의 입력 구현하기
- 구입 금액의 단위 테스트 통과를 위해 숫자가 아닐경우, 음수일 경우, 0일경우, 1000원단위가 아닐경우 예외처리 기능 구현
- 로또 금액 상수로 입력
- 구입 금액 단위 테스트 구현 완료하기
- 먼저 당첨 번호 입력값 구현
- 당첨 번호 숫자가 아니거나 ,로 구분을 안하는 경우, 0미만 45초과일 경우, 중복된 숫자인 경우, 로또 번호가 6개가 아닌 경우 예외처리 기능 구현
- 당첨 번호 숫자 입력 단위 테스트 구현 완료
- 구매 금액을 입력한 값에 따라 로또 구매 기능 구현 (Lotto.js에 getNumbers 메서드를 넣고 구입 금액을 1000으로 나눈 값만큼 새로운 인스턴스 객체를 생성) 후 출력하는 구현까지 완료
- 보너스 숫자 입력과 유효성 검증 구현 완료
- 보너스 숫자 1미만 45초과일 경우, 숫자가 아닐 경우, 중복될 경우 단위 테스트 구현 완료
- 객체 지향을 공부한 결과 기존의 winningNumberValidate의 검사를 Lotto 클래스에 validate에 추가함
- 객체 지향을 지향하기 위해 새로운 WinningLotto의 객체를 만든다음 당첨 로또 번호는 기존의 Lotto 유효성 검사를 진행하고 기존의 bonusNumberValidate를 WinningLotto의 보너스 번호 유효성 검사로 바꿈
- Lotto 클래스에 당첨 번호와 맞는지의 메서드를 구현하기 위해 getMatchCount 메서드를 구현

## 배운점

- 문자열을 숫자열로 변환할 때 만약 숫자가 아닌 경우 NaN이 나타난다. 기존에 검사를 통해 `변수 === NaN` 일 경우 조건이 통과될 줄 알았는데, Number.isNaN() 메서드를 통해야 정확하게 가능하다. `Number.isNaN(변수)`
